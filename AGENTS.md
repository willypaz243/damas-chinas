## Architecture Overview

Chinese Checkers two-player game built with React 19 + Vite + TypeScript. No Redux or Context — all state flows through a single `useEngine` hook that wraps the immutable `GameEngine` class.

### Core Flow

```
App.tsx
 └─ useEngine() hook
     ├─ GameEngine (src/engine/game.ts) — owns all game logic
     ├─ useState for selectedCell, validMoves (UI selection state)
     └─ GameState (returned by engine.getState()) → props to components
```

### Engine Layer (`src/engine/`)

| Module | Role |
|--------|------|
| `game.ts` | `GameEngine` class — move validation, execution, turn switching, undo via snapshot, victory check |
| `board.ts` | `HexBoard` — hex grid representation (axial coords), neighbor lookup, board shape generation |
| `types.ts` | Shared types: `PlayerId`, `HexCoord`, `Cell`, `Move`, `GameState`, `GameConfig`, interfaces (`IBoard`, `GameEngine`) |
| `constants.ts` | Board constants: `BOARD_COORD_MAX=8`, `TRIANGLE_CUTOFF=4`, `TOTAL_BOARD_SIZE=121`, `PIECES_PER_PLAYER=10` |
| `jump-chain.ts` | `JumpChainFinder` — recursive multi-jump chain discovery for Chinese Checkers hopping rules |
| `target-zone.ts` | `TargetZoneCalculator` strategy interface + `SouthTargetZone` / `NorthTargetZone` implementations for victory detection |
| `utils.ts` | `hexToPixel(q,r,size)` for SVG rendering, `cellKey(q,r)` for Map serialization |

### UI Layer (`src/components/`)

| Component | Purpose |
|-----------|---------|

### State Shape (`GameState` in `types.ts`)

```ts
interface GameState {
  board: Map<string, Cell>;        // key = "q,r" axial coord string
  players: PlayerConfig[];
  currentPlayerIndex: number;
  currentPlayer: PlayerConfig;
  moveHistory: Move[];
  selectedPiece: HexCoord | null;
  validMoves: HexCoord[];
  winner: PlayerConfig | null;
  isGameOver: boolean;
}
```

## Conventions

- **Engine owns logic, UI is dumb**: Components receive props and emit callbacks. No component calls engine methods directly.
- **Hex coordinates**: Axial system (q, r). Board range is [-8, 8] with triangle cutoff at 4 for the star shape.
- **Selection state lives in the hook**: `selectedCell` and `validMoves` are React state in `useEngine`, not in `GameState`. This keeps engine pure (no UI coupling) while giving the hook control over click handling.
- **Snapshots for undo**: `GameEngine` maintains a `GameState[]` snapshot stack. `undoLastMove()` pops the last snapshot and restores it.
- **Victory condition**: A player wins when all 10 of their pieces land in the opponent's target zone (calculated via `TargetZoneCalculator`).

## Key Implementation Details

### Move Types

- `"step"`: Adjacent empty cell move
- `"jump"`: Multi-hop chain via intermediate pieces (Chinese Checkers rules)
- `JumpChainFinder` uses a visited-set to prevent infinite loops during recursive exploration

### Board Shape

The hex board is generated by filtering axial coordinates within `[-8, 8]` that satisfy the star-of-David shape constraint: at most one coordinate's absolute value exceeds `TRIANGLE_CUTOFF (4)`. This yields 121 valid cells.

### Adding a New Component

1. Create `src/components/ComponentName/ComponentName.tsx` and any sub-components
2. Export from the index file in the same directory
3. Wire into `App.tsx` via props or the `useEngine` hook return value
4. Add CSS modules in `src/styles/` if needed

### Adding Engine Logic

1. Modify `GameEngine` in `src/engine/game.ts` — keep methods pure (no DOM access)
2. Update interfaces in `types.ts` if public API changes
3. Add tests in co-located `*.test.ts` files
4. Verify with `pnpm test --run`
